# 打工人小账本

一个桌面优先、移动端可用、本地优先的个人收支账本。核心路径只有三件事：记录实际收入或支出，查看本月结余，按周或按月复盘。智能助手只是更快的输入和查询入口，不改变“实际流水是账本事实”的原则。

当前版本已完成整体重设计，视觉与信息密度参考 ezBookkeeping，账户、分类、标签、转账和报表结构参考 MoneyNote 的产品能力，同时保持普通用户可直接上手。

## 运行

```powershell
npm install
npm run check
npm start
```

启动后打开 `http://127.0.0.1:4173`。设计演示数据可通过 `http://127.0.0.1:4173/?demo=1` 查看，演示模式不会写入真实账本。

## 智能助手模型设置

在“智能助手 → 模型设置”中填写兼容接口的基础地址（通常以 `/v1` 结尾）和模型名称；应用会请求 `{基础地址}/chat/completions`。API Key 对本地兼容服务可留空。保存前会先执行连接测试；即使不配置模型，本地基础记账和常用账本问答也可以直接使用。

### Agent 处理链路

助手不是把整段输入直接丢给模型后再盲信结果，而是按以下顺序处理：

1. 前端限制单次输入 1000 字符，服务端先用确定性预处理器抽取金额、日期、数量、退款/转账语义和分类候选。
2. Agent 加载 `agent/AGENT.md` 及 `agent/skills/` 下的领域规则，让模型只在账本允许的类型、分类和账户中生成 JSON 草稿。
3. 多笔记账最多执行一轮受控 ReAct：模型生成草稿，调用本地 `validate_transaction_drafts` 工具校验笔数、金额、日期和字段，再根据校验结果修正一次；查询和分析可调用只读的流水搜索、消费习惯和偏好工具。
4. 前端再次做金额和字段归一化，草稿只进入用户审核卡片；确认按钮才会正式写入账本。

工具定义和执行器位于 `agent/tools.mjs`，Agent 编排位于 `agent/agent.mjs`。本地草稿会先立即显示，模型在后台增强；单笔请求只走一次模型调用，多笔请求最多两次，后台超时上限分别为 45 秒和 90 秒，但不会阻塞用户审核和入账。运行 `npm run test:agent` 可回归验证多日期、多金额、退款、口语金额、严格 JSON、消费分析工具和 Agent 工具循环。

## 已实现

- 首页：本月收入、支出、结余、最近流水、账户余额、收支趋势和总预算。
- 记一笔：支出、收入、账户间转账；支持金额、分类、账户、时间、标签和备注。
- 流水：按月份查看，支持关键词、类型和账户筛选，支持编辑与删除。
- 报表：每周、每月收入支出汇总、趋势图、支出分类和记录天数。
- 账户：银行卡、支付平台、现金、信用卡、储蓄账户等类型，余额由期初余额与流水自动计算。
- 分类：内置常用收入与支出分类，可添加自定义分类。
- 工资到手估算：税前工资减去个人社保、公积金、个税和其他扣除；也可跳过估算，直接记录实际到账。
- 智能助手：用“今天午餐 28 元，微信支付”生成可编辑草稿；也可询问本月支出、收入、结余、最大支出分类、分类环比和消费习惯。支持“记住 GPT会员归类为订阅服务”等偏好建议，但必须手动确认后才保存。
- 写入保护：助手不会直接落账，金额、类型、分类、账户、时间和备注必须在草稿卡片中确认后才写入流水。
- 模型连接：不配置模型也可使用本地基础解析与常用账本问答；需要更复杂的理解时，可在设置中填写 OpenAI-compatible API 地址、模型名和可选 API Key，并先测试连接。
- 本地备份：JSON 导出与导入，账本数据默认保存在浏览器 IndexedDB。
- 响应式：桌面侧栏与移动端底部导航，支持键盘焦点和减少动态效果偏好。

## 产品范围

真实时薪、工作成本、自由基金、安全垫月数和情景模拟已经退出产品范围。工资、奖金、补发、试用期 80% 工资或只工作半个月等情况，都作为当月实际收入直接记录，不要求用户先建立工时或计薪模型。

## 数据与隐私

- 主要数据存放在 IndexedDB：`transactions`、`profile_settings`、`categories`、`accounts`、`agent_messages`、`agent_memory`。
- 不要求注册，不会自动上传账本。只有用户主动发送消息且已经配置外部模型时，才会把本次问题、必要汇总和最近流水摘要交给兼容模型。
- API Key 默认只放在当前浏览器会话；只有勾选“在此设备记住”才会写入浏览器本地存储。Key 不会进入账本备份。
- 换设备、换浏览器或清理站点数据前，请先在设置中导出备份。
- 导入会先检查基本结构，并在用户确认后替换当前账本。
