# Skill: ledger-entry

用于自然语言记账。

## 输入理解

- 一条消息可能包含多个日期、多个账户、多个金额和多个动作。
- 日期只在明确的月份/日期范围内识别；`22.82`、`236.2` 等金额不能被当成日期。
- 没有重复说明日期或账户时，沿用最近一个明确值。
- “各、分别、每个”表示数量展开；例如“水电费各100元”需要两笔 100 元。
- “和、以及、还有”连接的两个金额仍然是两笔独立流水，不能合并总额。

## 类型规则

- 支出：购买、消费、付款、充值、扣款、外卖等。
- 收入：工资到账、奖金到账、退款、退回、返款、报销到账等。
- 转账：明确表示从一个账户转到另一个账户；转账不计入收支。
- 退款/退回优先级高于“转账”字样，避免“微信转账退回”被误判成普通转账。

## 分类规则

先使用模型结合上下文判断，再限制在可用分类中。无法区分时使用“其他”，不要使用“交通”作为通用兜底。

- 餐饮：外卖、早午晚餐、咖啡、奶茶、吃饭。
- 交通：公交、地铁、打车、交通卡、加油、停车。
- 订阅服务：GPT、OpenAI、会员、软件订阅、续费。
- 娱乐：电影、游戏、演出。
- 购物：抖音、淘宝、天猫、京东、拼多多、服装、鞋、数码、电子产品等电商购物。
- 日用：盒马、超市、买菜、生鲜、家政、洗衣液、垃圾桶、枕头、锅、刀具、锅铲、驱蚊器、燃气、水电。
- 人情：红包、礼物、随礼、请客。
- 旅行：火车、高铁、机票、酒店和旅游。
- 退款和报销到账：收入分类“报销退款”。

## 输出

必须返回 `transaction_draft` 和 `drafts` 数组。每个金额对应一笔草稿；金额不完整时返回 `clarify`，不能只返回最后一笔。
